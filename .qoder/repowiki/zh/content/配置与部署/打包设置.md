## 性能考量
- 样式体积控制
  - Tailwind content 范围明确，避免生成未使用类导致的体积膨胀。
  - Autoprefixer 在生产构建中减少手动前缀维护成本。
- 构建速度
  - electron-vite 的外部化依赖插件有助于减少主进程打包体积与时间。
- 运行时性能
  - 主进程禁用沙箱但开启上下文隔离，结合最小权限原则，降低安全风险同时保证功能可用性。

## 故障排查指南
- 打包失败或产物缺失
  - 确认已先执行构建脚本再触发打包命令。
  - 检查主进程入口是否指向实际产物路径。
- Windows 安装包无法安装或缺少图标
  - 确认 icon 路径存在且为有效 ICO 格式。
  - 若需要自定义安装界面或语言，请在 NSIS 配置中补充相应模板与资源。
- 样式未生效或构建报错
  - 检查 Tailwind content 路径是否覆盖到新增组件。
  - 确保 PostCSS 插件顺序正确（tailwindcss → autoprefixer）。
- 运行时窗口与 IPC 异常
  - 核对预加载与主进程通信接口是否与渲染侧调用一致。
  - 开发模式下 ELECTRON_RENDERER_URL 是否正确指向本地地址。

## 结论
红ophoto 的打包配置以 Electron Builder 为核心，结合 electron-vite 与 Tailwind CSS/PostCSS，实现了简洁高效的跨平台构建与打包流程。当前 Windows 平台采用 NSIS 安装器，具备可自定义安装路径的能力。样式体系通过 Tailwind 的按需生成与 Autoprefixer 的兼容处理，兼顾体积与可维护性。后续可在 NSIS 配置中进一步完善安装界面与快捷方式策略，并根据需要扩展代码签名与自动更新能力。

### 不同操作系统平台的打包差异与特殊要求
- Windows（NSIS）
  - 支持自定义安装路径与非一键安装；可扩展快捷方式与注册表项。
- macOS（未在当前配置中启用）
  - 建议配置 DMG 或 PKG，配合代码签名与公证流程。
- Linux（未在当前配置中启用）
  - 可选 DEB/RPM 或 AppImage；需考虑权限与桌面集成。

### 代码签名与自动更新建议
- 代码签名
  - Windows：使用 p12 证书与 Electron Builder 的 signingHashAlgorithms、publisherName 等字段进行签名。
  - macOS/Linux：遵循平台签名与公证流程，确保安装包可信。
- 自动更新
  - 使用 S3、GitHub Releases 或私有更新服务器；在主进程中集成 autoUpdater 并在构建配置中启用 publish。
- 权限设置
  - Windows：根据需要声明安装目录写权限与注册表项；避免过度授权。
  - macOS/Linux：遵循最小权限原则，必要时请求用户授权。
