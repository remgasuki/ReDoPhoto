## 简介
本设计文档聚焦于红ophoto的用户界面系统，围绕基于React的渐进式四步操作流程：导入步骤、扫描步骤、比较步骤与执行步骤展开。文档详细说明各UI组件的功能职责、状态管理（Zustand）、用户交互模式、响应式设计（Tailwind CSS）与主题定制、组件层次结构与数据流、用户体验优化与无障碍支持，以及组件的props接口、事件处理与生命周期管理。

**更新** 本版本重点反映了用户界面系统的模块化架构升级，新增侧边栏导航组件提供统一的功能入口，三大核心功能模块（去重、方向调整、重命名）采用独立组件设计，所有组件已集成完整的主题颜色系统，实现了统一的视觉风格与主题切换能力。特别地，主题系统现已包含七种不同的主题选项，其中"灰色(gray)"主题作为新的默认选择，为表单输入元素提供了统一的视觉样式。

## 项目结构
渲染层采用Electron + Vite + React + TypeScript + Tailwind CSS，状态管理使用Zustand。应用入口负责挂载根组件，四大步骤组件通过共享状态驱动切换；设置面板独立弹窗，标题栏提供设置入口；新增侧边栏导航提供模块化功能入口；样式通过Tailwind全局注入与自定义动画、滚动条等增强。新增主题系统通过专门的类型定义与状态管理实现，支持七种不同的主题颜色方案。

## 架构总览
应用采用"视图-状态-服务"三层架构，现支持模块化功能架构：
- 视图层：四个步骤组件与通用UI组件，负责用户交互与反馈；新增侧边栏导航与功能模块组件。
- 状态层：Zustand Store（扫描、去重决策、设置、导航、**主题**），统一管理跨组件状态与动作。
- 服务层：主进程服务封装文件扫描、哈希计算、分组与执行逻辑，通过IPC回调向渲染层推送进度。

## 详细组件分析

### 导入步骤（ImportStep）
- 功能要点
  - 文件夹选择与拖拽区域交互。
  - 调用主进程扫描文件夹，监听扫描进度。
  - 计算SHA-256哈希，按设置可选计算感知哈希。
  - 将重复组写入扫描状态，进入对比阶段。
  - 错误处理与提示。
- 状态管理
  - 使用扫描状态：设置阶段、文件夹路径、文件列表、进度、错误、重复组、执行结果。
  - 使用设置状态：读取检测模式与阈值。
  - **新增** 使用主题状态：获取当前主题颜色配置，包括inputBg、inputBorder、inputText属性。
- 用户交互
  - 点击/拖拽选择文件夹。
  - 点击开始扫描，禁用条件为未选择文件夹。
  - 显示当前检测模式指示。
- 性能与体验
  - 分阶段进度回调，避免阻塞UI。
  - 无文件或无重复时友好提示并回退到导入阶段。

### 对比步骤（CompareStep）
- 功能要点
  - 分页展示重复组，每组左右两张图对比。
  - 提供"保留左/右/全部保留左/全部保留右/清除选择"等批量操作。

- 状态管理
  - 使用扫描状态：重复组列表、当前阶段。

- 用户交互
  - 图片卡片状态高亮（保留/移除）。
  - 分页导航与"重新开始"按钮。
  - 执行按钮在全部决策完成后可用。
- 性能与体验
  - 分页渲染，避免一次性渲染大量重复组。
  - 加载缩略图时占位与骨架反馈。

## 主题系统

### 主题颜色系统

应用实现了完整的主题颜色系统，通过专门的主题类型定义和状态管理实现，现包含七种不同的主题选项：

- **主题类型定义**：在`theme.ts`中定义了完整的主题颜色配置，包括主色调、辅助色、背景色、文字色、输入框样式等。
- **主题状态管理**：通过Zustand实现主题状态的集中管理，支持主题切换与持久化。
- **组件主题集成**：所有核心组件都集成了主题支持，确保视觉一致性。

**更新** 主题系统现已包含以下七种主题：
- 深灰色（black）：深色主题，适合夜间使用
- 白色（white）：经典浅色主题
- 米色（beige）：温暖的中性色调
- 天蓝色（skyblue）：清新的蓝色主题
- 深蓝色（darkblue）：专业的深蓝主题
- 克莱因蓝（kleinblue）：浓郁的蓝色主题
- **灰色（gray）**：**新增** 默认主题，提供统一的表单输入样式

### 主题输入框样式属性

**新增** 主题系统现已为所有主题添加了三个关键的输入框样式属性，确保表单输入元素在所有主题下保持一致的外观：

- **inputBg**：输入框背景色，确保在不同主题下都有合适的背景
- **inputBorder**：输入框边框色，提供清晰的边界识别
- **inputText**：输入框文字色，保证文字可读性

这些属性的应用确保了：
- 所有主题下的输入框具有一致的视觉外观
- 文字可读性在不同背景下得到保证
- 边框与背景的对比度符合无障碍标准

### 主题状态模型与动作
- **themeStore**
  - 状态：当前主题配置、主题切换历史、主题持久化状态。
  - 动作：切换主题、应用主题、保存主题偏好、重置主题。

### 主题切换机制
- **实时响应**：主题切换时，所有组件实时响应颜色变化。
- **持久化存储**：用户偏好的主题设置会持久化到本地存储。
- **系统集成**：支持跟随系统主题设置的自动切换。

### 主题组件集成
所有核心组件都已集成主题支持：
- **ImportStep**：导入界面的颜色方案与主题一致，包括inputBg、inputBorder、inputText
- **ScanningStep**：扫描进度条与图标应用主题颜色，包括inputBg、inputBorder、inputText
- **CompareStep**：对比界面的按钮、卡片、进度等元素使用主题色，包括inputBg、inputBorder、inputText
- **ExecuteStep**：执行界面的进度、按钮、结果展示使用主题色，包括inputBg、inputBorder、inputText
- **SettingsPanel**：设置界面的表单控件、按钮使用主题色，包括inputBg、inputBorder、inputText
- **TitleBar**：标题栏的背景、文字、按钮使用主题色
- **Sidebar**：侧边栏导航的背景、文字、按钮使用主题色
- **功能模块组件**：去重、方向调整、重命名模块的界面元素使用主题色

### 灰色主题特性

## 性能考虑
- 渲染层
  - 分页渲染重复组，减少单次DOM压力。
  - 缩略图懒加载与取消机制，避免内存泄漏。
  - 进度回调节流与异步让出，保证UI流畅。
  - **新增** 主题切换优化：使用CSS变量缓存主题颜色，减少重绘。
  - **新增** 模块化渲染：功能模块组件按需渲染，减少初始负载。
- 状态层
  - Zustand以最小粒度订阅，避免不必要重渲染。
  - Map存储决策，O(1)查询与更新。
  - **新增** 主题状态优化：主题切换时只更新受影响的组件。
  - **新增** 导航状态优化：navStore仅管理导航状态，避免状态膨胀。
- 主进程
  - 扫描与执行过程中分批处理与事件循环让出，避免阻塞。
  - 拷贝/删除操作批量写入，减少IO开销。

  - **新增** 主题设置不同步：检查主题状态管理与组件订阅。
  - **新增** 输入框样式异常：检查inputBg、inputBorder、inputText属性是否正确应用。

  - 侧边栏导航失效：检查navStore状态与Sidebar组件绑定。

### Zustand 状态模型与动作
- scanStore
  - 状态：阶段、文件夹路径、文件列表、进度、错误、重复组、执行结果。
  - 动作：设置阶段、路径、文件、进度、错误、重复组、执行结果、重置。
- dedupStore
  - 状态：决策Map。
  - 动作：设置决策、保留左/右、全部保留左/右、清空、导出决策数组、统计、是否存在决策。
- settingsStore
  - 状态：设置对象与加载标志。
  - 动作：加载设置、更新设置（含IPC同步与本地回退）。
- **新增** navStore
  - 状态：当前激活的模块、导航历史、模块切换状态。
  - 动作：切换模块、重置导航、保存导航状态。
- **新增** themeStore
  - 状态：当前主题配置、主题切换历史、主题持久化状态。
  - 动作：切换主题、应用主题、保存主题偏好、重置主题。
